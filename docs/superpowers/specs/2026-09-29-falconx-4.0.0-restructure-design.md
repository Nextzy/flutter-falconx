# flutter-falconx 4.0.0 restructure — design

Date: 2026-09-29
Status: approved in conversation, pending written review

## Goal

Release `flutter_falconx_core` 4.0.0 so that a consumer app can list any single package of this repository
(`flutter_faltool`, `flutter_falstore`, `flutter_falmodel`, `flutter_falconnect`, or the umbrella `flutter_falconx`)
as a git dependency pinned to one tag, on every Flutter platform: Android, iOS, macOS, Windows, Linux, and web.

The repository follows the conventions already proven in `dart-falconx` 2.3.1 (git sibling dependencies,
`lib/src/src.dart` prelude, drift test, consumer skill), so the two repositories read the same way.

## Non-goals

- Editing the mangmee app. It switches from absolute `path:` dependencies to git tags in its own change after 4.0.0
  is tagged.
- Moving internal files under `lib/src/` beyond the prelude. Only `src/src.dart` is created now.
- Publishing to pub.dev. Every package keeps `publish_to: none`.

## Current state (before this work)

- Root `pubspec.yaml` is `flutter_falconx_core` 1.0.0 with a `workspace:` of five packages; `flutter_falkit` is
  declared `resolution: workspace` but is missing from that list.
- Every package is at version 1.0.0 while the last git tag is `3.11.4` (made when the root was `falconx_project`).
- Sibling dependencies use `path: ../<package>`. A consumer that lists `flutter_falconx` from git therefore cannot
  resolve `../flutter_faltool`.
- `flutter_faltool` fails `flutter analyze` with 14 `Undefined name 'Platform'` errors because `dart_faltool` 2.3.1
  stopped re-exporting `universal_io`.
- Uncommitted work already on `develop`: `url_strategy` removed from `flutter_faltool`; `ImageCompressTool` moved
  from `flutter_falkit/lib/tools/` to `flutter_faltool/lib/tools/`; `flutter_falkit/LICENSE` and every
  per-package `analysis_options.yaml` deleted in favour of one root file.

## Decisions

| # | Decision | Chosen |
|---|----------|--------|
| 1 | Next version | `4.0.0` for the root and all five packages |
| 2 | Sibling dependency source | git dependency with `ref:` pinned to the version, same as dart-falconx |
| 3 | `flutter_falkit` | removed entirely |
| 4 | `ImageCompressTool` on Windows and Linux | hybrid engine: `flutter_image_compress` where native, `package:image` elsewhere |
| 5 | `Platform` fix | `defaultTargetPlatform` and `kIsWeb`; no `universal_io` |
| 6 | Documentation scope | rewrite `CLAUDE.md`, add drift test, add consumer skill |
| 7 | Export structure | delete every `lib.dart`; add `lib/src/src.dart` prelude per package |

## 1. Package layout and dependency graph

```
flutter_falconx      umbrella: bloc base classes, routers, view builders; re-exports the four below
    ↓
flutter_falconnect   Dio/Retrofit/WebSocket engine, connectivity          → dart_falconnect 2.3.1
    ↓
flutter_falmodel     WidgetDataState, models, extensions                   → dart_falmodel 2.3.1
    ↓
flutter_faltool      PlatformChecker, DeviceIdGenerator, ImageCompressTool, print utils → dart_faltool 2.3.1

flutter_falstore     SecureStorage; depends on flutter_faltool only
```

Rules:

- A package depends only on packages below it in the diagram. `flutter_falstore` depends on `flutter_faltool` and
  nothing else in this repository. `flutter_faltool` depends on no sibling.
- A sibling dependency is always declared as

  ```yaml
  flutter_faltool:
    git:
      url: https://github.com/Nextzy/flutter-falconx
      ref: 4.0.0
      path: flutter_faltool
  ```

  The URL is spelled exactly this way everywhere: no `.git` suffix, no SSH form. Pub treats each spelling as a
  distinct source and rejects a mix. Inside the workspace pub resolves the sibling to the local folder regardless of
  the declared source, so development needs no override file.
- `dart_fal*` dependencies keep `ref: 2.3.1`, the latest dart-falconx tag.
- Root `workspace:` lists exactly the five packages. `flutter_falkit/` is deleted with `git rm -r`.
- Never declare a dependency that a `dart_fal*` package already re-exports; it arrives transitively.

## 2. Versioning and release

- `version: 4.0.0` in the root and the five package pubspecs. Every sibling `ref:` is `4.0.0`.
- `environment.sdk: ">=3.13.0 <4.0.0"` in every pubspec; root adds `flutter: ">=3.44.0"` because
  `app_links` 7 and `flutter_local_notifications` 22 require it.
- Release procedure, recorded in `CLAUDE.md`:

  ```bash
  git flow release start 4.0.0
  # set version: and every sibling ref: to 4.0.0
  melos run get && melos run analyze && melos run test
  git commit -am "chore: release 4.0.0"
  git flow release finish 4.0.0      # tags 4.0.0 (empty tag prefix), merges main and develop
  git push origin main develop --tags
  ```

  Feature work lands on `develop` first; the release branch carries only the version bump.
- Drift test `flutter_falconx/test/internal_dependencies_test.dart`, ported from dart-falconx, fails when: a package
  version differs from the root; a sibling is not a git dependency; `url` differs from the canonical spelling;
  `ref` differs from the version; `path` differs from the sibling name; `flutter_faltool` lists a sibling;
  `flutter_falstore` lists anything but `flutter_faltool`; a barrel exports `src/` or a `lib.dart` exists.
  `yaml` is added as a dev dependency of `flutter_falconx`.
- `CHANGELOG.md` at the root lists the 4.0.0 breaking changes (section 7).

## 3. Platform support

### 3a. ImageCompressTool hybrid engine (`flutter_faltool`)

```
lib/tools/
  image_compress.dart              public facade; picks an engine from PlatformChecker and delegates
  src/image_compress_engine.dart   abstract ImageCompressEngine { Future<Uint8List> compress(bytes, config, format) }
  src/native_engine.dart           flutter_image_compress → Android, iOS, macOS, web
  src/dart_engine.dart             package:image inside compute() → Windows, Linux
```

- Public API keeps every name (`compressFile`, `compressBytes`, `compressAndSaveFile`, `batchCompressFiles`,
  `getCompressionResult`, `estimateCompressedSize`, `ImageCompressProfile`, `ImageCompressConfig`,
  `CompressionResult`, `ImageCompressException`) but file parameters and results change from `dart:io` `File` to
  `XFile` from `cross_file`, which exists on every platform.
- No file under `lib/` imports `dart:io`. Engine selection happens at runtime; both engines compile everywhere.
- Dart engine formats: JPEG and PNG. WebP and HEIC on Windows or Linux throw `UnsupportedError` naming the
  platform and format. WebP encode support in `package:image` is verified during implementation; if present, WebP
  joins the list.
- Output location: native and desktop write to the `path_provider` temporary directory; web returns
  `XFile.fromData(bytes)` with no path.
- New dependencies in `flutter_faltool`: `image`, `cross_file`.

### 3b. Platform detection

- `PlatformChecker.isAndroid` and siblings compare `defaultTargetPlatform` with `TargetPlatform` values;
  `isWeb` stays `kIsWeb`. On web `defaultTargetPlatform` reports the browser's OS, which the existing `*Native` and
  `*OnWeb` getters already distinguish.
- `DeviceIdGenerator` fallback strings use `defaultTargetPlatform.name` instead of `Platform.operatingSystem`,
  `Platform.operatingSystemVersion`, and `Platform.localHostname`.
- `flutter_falconnect` stops exporting `dart:io`.

### 3c. Rule

`dart:io` may appear in `lib/` only in the `if (dart.library.io)` branch of a conditional import. Feature gaps per
platform are listed in a table in `CLAUDE.md` (today: `ImageCompressTool` WebP/HEIC on Windows and Linux;
`flutter_udid` absent on web, never called there).

## 4. Dependencies

### 4a. Remove duplicates of dart-falconx re-exports

| Package | Remove | Reason |
|---------|--------|--------|
| `flutter_falconnect` | `dio`, `retrofit`, `web_socket_channel`, `dio_cache_interceptor`, `freezed_annotation` | re-exported by `dart_falconnect` and `dart_faltool`; no direct import in this repo |
| `flutter_falconnect` dev | `build_runner`, `freezed`, `json_serializable`, `retrofit_generator` | no `@freezed`, `@RestApi`, or generated file exists here |
| `flutter_falmodel` | `dio` and its export in the prelude | no Dio type used; matches `dart_falmodel` |
| `flutter_faltool` dev | `flutter_gen_runner` | no assets |
| `flutter_falconx`, `flutter_falconnect`, `flutter_falstore` | `ansicolor` | only used by the duplicated print helpers, which move to `flutter_faltool` |

### 4b. Consolidate print helpers

`printInfo`, `printError`, `printSuccess` exist four times. They move to
`flutter_faltool/lib/utils/print_utils.dart`, exported through `utils/utils.dart`; the other three copies are
deleted. Existing callers keep working because every package exports `flutter_faltool`.

### 4c. Keep as intentional re-exports

`provider`, `bloc_concurrency`, `flutter_bloc`, `app_links`, `flutter_local_notifications`, `connectivity_plus`,
`leak_tracker`, `rate_limiter`, `share_plus`, `device_info_plus`, `package_info_plus`, `flutter_udid`,
`shared_preferences`, `flutter_secure_storage`, `path`, `path_provider`.

### 4d. Upgrade

- `app_links` `^7.2.1`, `flutter_local_notifications` `^22.3.1` in `flutter_falconx` (re-export only).
- Add `image`, `cross_file` (`flutter_faltool`), `yaml` (`flutter_falconx` dev).

## 5. Export structure

Per package:

```
lib/<package>.dart     public barrel only, ordered dart: → package: → local
lib/src/src.dart       internal prelude: exports the package's own barrel plus package:flutter/foundation.dart
                       and whatever internal files need; never exported by the barrel
```

- Every `lib/lib.dart` is deleted. Internal files change `import 'package:<pkg>/lib.dart'` to
  `import 'package:<pkg>/src/src.dart'` (falconx 26 files, falconnect 3, falmodel 3, faltool 3, falstore 1).
- Each barrel re-exports the sibling one level below it (`flutter_falconnect` → `flutter_falmodel` →
  `flutter_faltool`; `flutter_falstore` → `flutter_faltool`). The umbrella `flutter_falconx` exports all four
  explicitly.
- `flutter_falconx.dart` drops the `flutter_falkit` export. Existing `hide Path` and `hide BaseResponse` clauses
  are re-evaluated after the restructure and kept only where the analyzer still reports a conflict.
- `library falstore;` is removed.
- Source files under `extensions/`, `utils/`, `tools/`, `engine/`, and so on stay where they are.

## 6. Documentation

### 6a. `CLAUDE.md`

Rewritten with the dart-falconx structure: Project overview (diagram and the rules above), Platform support,
Commands (melos scripts table), Architecture (one paragraph per package), Release (section 2 procedure and drift
test), Skill maintenance (public API change ⇒ update the skill in the same change), Gotchas, Configuration (single
root `analysis_options.yaml`).

### 6b. Consumer skill `skills/flutter-falconx-package/`

```
SKILL.md                  setup, capability map, do-not-reinvent, gotchas
references/state.md       FalconBloc, WidgetDataState blocs, cubits, validators, view builders
references/routing.md     routers
references/network.md     flutter_falconnect engine, InternetConnectionBloc, connectivity
references/storage.md     SecureStorage
references/utils.md       PlatformChecker, DeviceIdGenerator, ImageCompressTool, print utils
references/third-party.md every re-exported package
```

HTTP, WebSocket, JSON-RPC, `Result`, and exception details are not repeated; `SKILL.md` points to the
`dart-falconx-package` skill. The public API inventory is produced during implementation by reading every barrel
and the files it exports.

## 7. Breaking changes for consumers (CHANGELOG 4.0.0)

1. `flutter_falkit` is gone. `ImageCompressTool` lives in `flutter_faltool`; falkit widgets, animations, styles,
   and extensions are no longer provided.
2. `ImageCompressTool` takes and returns `XFile` instead of `File`.
3. `Platform`, `File`, and other `dart:io` names are no longer re-exported; import `dart:io` or `universal_io`
   in the app.
4. `url_strategy` is gone; call `usePathUrlStrategy()` from `flutter_web_plugins` in the app.
5. `flutter_local_notifications` 22 (named parameters since 20.0.0) and `app_links` 7.
6. Sibling packages are git dependencies pinned to a tag; apps list any mix of packages with the same tag.
7. `dio`, `retrofit`, and related names still arrive through `dart_falconnect`; no change for consumers.

## 8. Verification

- `melos run analyze` reports 0 errors.
- `melos run test` passes, including the drift test and `flutter_faltool/test/tools/image_compress_test.dart`
  (engine selection per platform via `debugDefaultTargetPlatformOverride`, real JPEG and PNG compression through
  the Dart engine from fixture bytes, `UnsupportedError` cases).
- `flutter test --platform chrome` in `flutter_faltool` for `platform_checker_test.dart` and
  `image_compress_test.dart` proves the package compiles for web.
- mangmee pointed at the local `develop` checkout passes `flutter analyze` before the tag is cut (not committed).

1. Remove `flutter_falkit`; fix root `workspace:`.
2. Export restructure (`src/src.dart`, delete `lib.dart`, print helpers into faltool).
3. Dependency cleanup and upgrades; sibling git dependencies; version 4.0.0 everywhere.
4. Platform fixes (`PlatformChecker`, `DeviceIdGenerator`, drop `dart:io` export).
5. `ImageCompressTool` hybrid engine with tests.
6. Drift test.
7. `CLAUDE.md`, `CHANGELOG.md`, consumer skill.
8. Verification, then `git flow release start 4.0.0` … `finish`.
